# Miniclaw 项目架构说明（面试版）

## 一句话定位
自托管的多渠道 AI Agent 工作台，把 AI Agent 从单次对话工具变成长期驻场的数字员工。

---

## 整体架构：四层职责边界

```
用户端（Web / 飞书 / 微信 / Telegram 等 7 个 IM）
         ↓
┌─────────────────────────┐
│  Backend（后端中枢）      │  ← 唯一有状态的地方
│  · 认证、SQLite 数据库    │
│  · 队列、调度、授权        │
│  · 不解释 Prompt！         │
└───────────┬─────────────┘
            ↓ stdin/stdout/IPC
┌─────────────────────────┐
│  Pi Runner（执行引擎）     │  ← 无数据库、无端口
│  · 只跑 Agent 执行循环     │
│  · 调用 LLM、执行工具     │
└───────────┬─────────────┘
            ↓
┌─────────────────────────┐
│  Workspace（工作区）      │  ← 文件真相锚点
│  · 每个 Agent 一个文件夹   │
│  · 隔离、可审计            │
└─────────────────────────┘
```

### 为什么这么分？
- **Backend 只管编排**，不管具体怎么跑 Agent——想换执行引擎就换，不动后端
- **Pi Runner 只管执行**，不管业务逻辑——它就是个跑 Agent 的黑盒
- **文件系统是唯一真相**，所有状态都能在文件里找到

## 你简历上写的 4 个点，逐个讲

### 1. 多渠道统一适配器（7 个 IM 接入）

**解决什么问题？**
7 个 IM 平台（飞书、微信、Telegram、QQ、钉钉、Discord、WhatsApp）各有各的 SDK，接入一个就要改一次核心代码，太乱了。

**怎么做的？**
定义了一个统一接口 `IMChannel`，里面就 5 个方法：
- connect / disconnect（连不连得上）
- sendMessage（发消息）
- setTyping（正在输入...）
- isConnected（在线吗）

每个 IM 平台写一个适配器，实现这个接口就行。

**加新渠道要干嘛？**
写个新适配器，实现 5 个方法，插进去就能用。核心代码一行都不用改。

---

### 2. 四层架构边界

**解决什么问题？**
编排逻辑和执行逻辑耦合在一起，想换个 Agent 引擎就得重写整个系统。

**怎么做的？**
四层各自只管自己的事，"明确不做什么"比"做什么"更重要：

| 层 | 做什么 | 不做什么 |
|---|---|---|
| Backend | 认证、队列、数据库、调度 | 不解释 Prompt |
| Pi Runner | 跑 Agent 循环、调 LLM | 不连数据库、不监听端口 |
| Workspace | 文件存储、隔离 | 不管权限、不管逻辑 |
| 客户端 | 展示、交互 | 不存令牌 |

**为什么用 stdin/stdout 不用网络 API？**
不用开端口，攻击面小，而且容器里跑的时候更安全。

---

### 3. 四段 Prompt 体系

**解决什么问题？**
自定义 Agent 人设都是一大段 Prompt，乱得很，而且很容易撑爆模型上下文窗口。

**怎么做的？**
把 Prompt 拆成 4 段，每段各管各的：

| 段落 | 管什么 | 能不能改 |
|---|---|---|
| IDENTITY | 我是谁（名字、身份） | 必填 |
| SOUL | 性格、说话风格 | 可选 |
| AGENTS | 工作规则、怎么做事情 | 必填 |
| TOOLS | 有哪些工具可以用 | 自动生成 |

每段上限 20000 字符，不会无限膨胀。

还有个上下文预算机制：快超了就自动压缩，不会撑爆模型窗口。

---

### 4. Workspace Memory 长期记忆

**解决什么问题？**
每次开新对话，Agent 就失忆了，之前聊的东西全忘了。

**怎么做的？**
单独搞了个结构化存储层，存 4 种知识：
- **fact**：事实（用户喜欢什么、项目背景）
- **decision**：做过的决定
- **lesson**：踩过的坑、经验教训
- **open_loop**：待办事项、没解决的问题

用 FTS5 全文检索（不是向量检索/RAG），搜关键词就能找到。

**和聊天记录的区别？**
聊天记录是"我们说过什么"，Memory 是"我们记住了什么"。
Memory 是从聊天里提炼出来的结构化知识，不是聊天记录的摘要。

## 你必须背熟的 4 件事

1. **一张架构图**：能在纸上画出来四层，说清楚谁管什么
2. **四段 Prompt**：IDENTITY / SOUL / AGENTS / TOOLS
3. **Memory 是什么**：结构化存 4 种知识，FTS5 搜索，不是 RAG
4. **七渠道适配器**：一个统一接口，每个 IM 实现一遍，加新渠道只要写适配器
